# ADR 0004: スポイラーボタンはメッセージ単位のcollectorで待ち受ける

- Status: Accepted
- Date: 2026-07-31
- Issue: #550

## Context

スポイラー投稿への返信には「ネタバレを見る」ボタンを付与し、押下時にメディアを
ダウンロードしてエフェメラルで返す。

従来の実装は、スポイラー投稿1件ごとに `client.on("interactionCreate", ...)` で
グローバルなリスナーを登録していた。このリスナーには解除経路がなく、プロセスが
生きている限り線形に増え続ける。`MaxListenersExceededWarning` とメモリ増加を招く。

ボタンの押下処理には、そのポストのEmbedとTweetデータが必要になる。従来の実装は
これらをクロージャで保持していた。したがってリスナーを廃止する場合、押下時に
これらをどう入手するかが設計上の分岐になる。

なお従来の実装でも、リスナーはインメモリであるためBot再起動でボタンは失効していた。
「ボタンが無期限に有効」という性質は元から存在しない。

## Decision

返信メッセージ単位の `createMessageComponentCollector` で待ち受ける。

- 待ち受け時間は24時間とする。`RedisReplyLogger` の既定TTL（`REDIS_TTL`、既定86400秒）と
  尺度を揃え、「1つのメッセージを24時間追跡する」という説明をリポジトリ全体で一貫させる。
- 待ち受け終了後は、返信メッセージを編集してボタンを `disabled` にし、ラベルを
  「表示期限が切れました」へ変更する。
- 上記の編集失敗（メッセージが既に削除されている場合など）はdebugログのみ記録して握りつぶす。
  表示の後始末であり、失敗しても機能に影響しないため。

EmbedとTweetデータは従来どおりクロージャで保持する。collectorの寿命が有限になったことで、
クロージャが保持するメモリも有限になる。

## Consequences

### Positive

- リスナーの累積が解消される。待ち受けはタイムアウトで自動的に破棄される。
- collectorのスコープが該当メッセージに閉じるため、`customId` による照合が不要になる。
  従来はすべてのボタン押下がすべてのリスナーを通過していた。
- リスナーを使わなくなったため、`sendSpoilerMessage` と `processSingleUrl` から
  `client` 引数を削除できた。依存が減った。
- ボタンの見た目から期限切れが分かる。

### Negative

- ボタンの有効期間に24時間の上限が入る。従来は「Bot再起動まで」であり、
  再起動が24時間より稀な環境では実質的に有効期間が短くなる。
- Bot再起動をまたいでボタンは有効にならない。従来と同じだが、本ADRでも解決していない。
- 待ち受け終了時に返信メッセージごとへ編集APIコールが1回発生する。

### Mitigation

- 期限切れのボタンは押下できない状態になるため、「押しても無反応」という
  分かりにくい失敗にはならない。
- 24時間はメディア展開の需要に対して十分長いと判断する。不足が判明した場合は
  `SPOILER_BUTTON_TTL_MS` の変更、または環境変数化で対応できる。

## Rejected alternatives

### 集約ハンドラ + Redis状態

`interactionCreate` を `src/index.ts` で1つだけ登録し、`customId` からルーティングする案。
Bot再起動をまたいでボタンを有効にできる利点がある。

採用しない理由は、押下時にEmbedとTweetデータを復元する必要があるため。
Redisへ永続化するか、Twitter APIから再取得するかの追加設計が要る。前者は
状態管理とTTLの設計、後者はAPI負荷と取得失敗時の扱いが新たに必要になる。

これはリークの修正ではなく「スポイラーボタンが再起動をまたいで生存する」という
機能追加であり、本Issueの目的と規模が異なる。将来この機能が求められた時点で、
独立した判断として扱う。

### 待ち受け時間を短くする（1時間など）

メモリをより早く解放できるが、スポイラーは後から見に来られる性質のコンテンツであり、
翻訳や時差をまたいだ閲覧を阻害する。24時間より短くする根拠が現時点でない。

### 期限切れ時に何もしない

実装は最小になるが、ボタンが見た目上は残り、押すとDiscordが
「インタラクションに失敗しました」を表示する。原因が利用者に伝わらない。

なお `disabled` にしたボタンはDiscord側でクリック自体を受け付けないため、
「押したら期限切れである旨を応答する」形は取れない。応答するには待ち受けを
生かし続ける必要があり、本ADRが解消したリークに戻る。このためラベル変更により
押す前に伝える形を採った。
