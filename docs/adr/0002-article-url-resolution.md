# ADR 0002: 記事本体URLは観測済み対応関係から解決する

- Status: Accepted
- Date: 2026-07-26
- Issue: #540

## Context

Xの記事本体URL `x.com/i/article/{articleId}` には共有元ポストIDが含まれない。
VxTwitter/FxTwitterは記事付きポストから記事情報を取得できるが、記事本体URLを
直接取得するAPIや、記事IDから共有元ポストを検索する無償の公開APIは提供していない。

有料のX APIは使用せず、取得可能な範囲で記事を展開する必要がある。

## Decision

記事付きポストを取得した際に、記事IDと共有元ポストURLの対応関係をRedisへ90日間保存する。
記事本体URLを受信した場合は、この対応関係から共有元ポストURLを解決し、
既存のVxTwitter/FxTwitter取得経路へ渡す。

対応関係がない記事は解決を試みず、共有元ポストURLの送信を案内する。
記事付きポスト自体は、対応関係の保存成否にかかわらず取得できたプレビューを表示する。

## Consequences

### Positive

- 有料API、ユーザー認証、Cookie管理が不要になる。
- 非公開APIの変更やbot対策に依存しない。
- 既存のTwitter adapterとフォールバックを再利用できる。
- Botが利用されるほど直接記事URLの解決可能範囲が広がる。

### Negative

- 初回観測前、またはTTL失効後の記事本体URLは解決できない。
- 別環境のBotが観測した対応関係は共有されない。
- VxTwitterのレスポンスでは、記事IDをポスト本文のURLから補完する必要がある。

### Mitigation

- キャッシュミス時は共有元ポストURLの送信を明示的に案内する。
- 再観測時にTTLを更新し、利用される記事の対応関係を維持する。
- 記事IDを取得できない場合も、記事付きポストのプレビュー表示は継続する。

## Rejected alternatives

### X APIの全文検索

記事IDや記事URLから共有元ポストを検索できる可能性はあるが、有料契約と
追加の認証・レート制限管理が必要になるため採用しない。

### Xの非公開GraphQL API

ログインCookieや内部APIへ依存し、仕様変更、利用規約、運用安定性の問題があるため採用しない。

### HTMLまたは検索結果のスクレイピング

記事ページから共有元ポストIDを安定して取得できず、bot対策やHTML変更の影響も大きいため採用しない。
